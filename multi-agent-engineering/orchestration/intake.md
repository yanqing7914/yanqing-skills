# Requirement Intake

Understand the real goal before delegating.

## Capture

- Outcome the user wants
- What may change
- What must not change
- Success criteria

## Ask The User When

- The target behavior is ambiguous
- Compatibility, migration, or data constraints are unknown
- Success cannot be checked
- A major design choice would lock the project

## Do Not Ask When

- The missing detail can be read from the repo
- The task is a small, obvious change
- The user already stated the constraint

If the request is still unclear after discovery, ask. Do not invent a goal.
